# Terraform — AWS platform substrate

Infrastructure-as-code for the Formless demo on AWS: the network, the managed
PostgreSQL database the app already speaks to (`DATABASE_URL`, PostgreSQL 16),
ECR registries for the container images built in Milestone 9, and the EKS
cluster that Milestone 11's Kubernetes manifests will target.

**Status: written and validated only.** `terraform fmt`, `terraform init`, and
`terraform validate` all pass with no AWS credentials present. Nothing has been
planned, applied, provisioned, or billed. An actual `apply` needs a real AWS
account and credentials and is a deliberate, captain-gated step.

## Layout

```text
infra/terraform/
├── versions.tf             # Terraform + provider pins, backend (local default, S3 documented)
├── variables.tf            # All knobs, demo-sized defaults
├── main.tf                 # Module wiring: vpc -> ecr, rds, eks
├── outputs.tf              # ECR URLs, RDS endpoint, EKS name/endpoint, SSM parameter names
├── terraform.tfvars.example
├── .gitignore              # state, plans, tfvars never committed
└── modules/
    ├── vpc/                # VPC, public+private subnets (2 AZs), IGW, single NAT gateway
    ├── ecr/                # api + web repositories: scan-on-push, immutable tags, untagged-image expiry
    ├── rds/                # PostgreSQL 16 (db.t4g.micro, 20 GiB gp3 autoscaling), subnet group, SG,
    │                       # generated master password stored in SSM SecureString (+ ready DATABASE_URL)
    └── eks/                # EKS cluster + managed node group, IAM roles, security groups,
                            # KMS secrets encryption, core addons, OIDC provider for IRSA
```

Sizing is deliberately demo-scale: 2 AZs, one NAT gateway, a single-AZ
`db.t4g.micro`, and one `t3.medium` node (max 2). Not enterprise.

Notes on the conventions used:

- Providers are pinned: `hashicorp/aws ~> 6.0`, `hashicorp/random ~> 3.7`,
  Terraform `>= 1.6.0`. `.terraform.lock.hcl` is committed.
- The EKS `kubernetes_version` variable defaults to `null`, which tells AWS to
  create the cluster on **the current default Kubernetes version for new
  clusters** at creation time. Pin it in `terraform.tfvars` when you want to
  manage version upgrades in code.
- No deprecated syntax (`domain = "vpc"` EIPs, `access_config` API-based
  authentication instead of aws-auth ConfigMap writes, `db_name` instead of
  the old `name` on `aws_db_instance`).
- The RDS master password is generated by `random_password` (32 alphanumeric
  chars, no specials so it embeds in URLs safely) and written to SSM Parameter
  Store as SecureString — nothing is hardcoded. **Terraform state still
  contains the values**, which is why the remote-state section below matters
  before any real apply.

## Working with the code (no credentials needed)

```sh
cd infra/terraform
terraform fmt -recursive   # canonical formatting
terraform init             # downloads pinned providers (needs registry access, not AWS)
terraform validate         # full schema/type check, no AWS credentials involved
```

`terraform validate` passes with zero AWS environment variables set — this is
the no-credentials CI gate. `terraform plan`, by contrast, always needs real
credentials; with none it fails at authentication, which is expected and safe.

## Plan / apply order

Everything is one root module; the dependency graph (VPC → EKS/RDS, RDS waits
on the EKS node security group) resolves the ordering internally, so a first
apply is:

```sh
cd infra/terraform
cp terraform.tfvars.example terraform.tfvars   # adjust region/variables
terraform init                                 # add -backend-config args if using S3 (below)
terraform plan -out=tfplan                     # review; needs AWS credentials
terraform apply tfplan                         # provisions VPC, ECR, RDS, EKS
terraform destroy                              # reverse order automatically on teardown
```

After apply, push the Milestone 9 images:

```sh
aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin <account>.dkr.ecr.us-east-1.amazonaws.com
docker build -f apps/api/Dockerfile . -t <api-repo-url>:<git-sha> && docker push <api-repo-url>:<git-sha>
docker build -f apps/web/Dockerfile . -t <web-repo-url>:<git-sha> && docker push <web-repo-url>:<git-sha>
```

Get the repo URLs with `terraform output ecr_api_repository_url` /
`ecr_web_repository_url`.

### Apply prerequisites

1. **AWS account** with permission to create VPCs, EKS, RDS, ECR, IAM roles,
   KMS keys, and SSM parameters.
2. **Credentials** in the environment (`aws sso login`, `aws configure`, or
   `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`/`AWS_SESSION_TOKEN`) — Terraform
   reads the standard AWS provider chain. No credentials belong in this repo.
3. **State bucket** (see below) unless you accept local state for the demo.
4. **Terraform >= 1.6** with registry access for `init`.

## Remote state

Local state (in `.terraform/`-adjacent `terraform.tfstate`, gitignored) is the
default right now, which is fine for the throwaway demo. The S3 backend is
already written into `versions.tf` as a commented block. Before any shared or
persistent apply:

1. Create the bucket and lock table:

   ```sh
   aws s3api create-bucket --bucket formless-tfstate-<account-id> --region us-east-1
   aws s3api put-bucket-versioning --bucket formless-tfstate-<account-id> \
     --versioning-configuration Status=Enabled
   aws s3api put-bucket-encryption --bucket formless-tfstate-<account-id> \
     --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"aws:kms"}}]}'
   aws dynamodb create-table --table-name formless-tfstate-locks \
     --attribute-definitions AttributeName=LockID,AttributeType=S \
     --key-schema AttributeName=LockID,KeyType=HASH \
     --billing-mode PAY_PER_REQUEST --region us-east-1
   ```

2. Uncomment the `backend "s3"` block in `versions.tf`, set the real bucket
   name/region, and re-run `terraform init` (it will offer to migrate state).

This matters more than usual because the RDS master password and DATABASE_URL
live in state; the bucket must be versioned and encrypted, and access-limited.

## Cost notes (rough monthly, us-east-1, demo defaults)

| Piece                                    | Resource                            | ~$/month                                  |
| ---------------------------------------- | ----------------------------------- | ----------------------------------------- |
| VPC, subnets, route tables, IGW          | `aws_vpc` + friends                 | $0                                        |
| NAT gateway (egress for private subnets) | `aws_nat_gateway`                   | ~$33 ($0.045/hr) + ~$0.045/GB processed   |
| EKS control plane                        | `aws_eks_cluster`                   | ~$73 ($0.10/hr, fixed)                    |
| Worker node                              | 1× t3.medium ON_DEMAND              | ~$30                                      |
| Worker node, SPOT option                 | same, `node_capacity_type = "SPOT"` | ~$10–12                                   |
| Node boot disk                           | 20 GiB gp3 EBS                      | ~$1.60                                    |
| PostgreSQL 16                            | db.t4g.micro single-AZ              | ~$11                                      |
| DB storage                               | 20 GiB gp3 (autoscales to 100)      | ~$2.30                                    |
| DB backups                               | 7-day automated                     | ~$0 within free tier of allocated storage |
| ECR                                      | both repos, a few GB of images      | ~$0.10/GB → $1–2                          |
| KMS key (EKS secrets)                    | `aws_kms_key`                       | ~$1                                       |
| SSM parameters                           | standard tier                       | $0                                        |
| **Total (ON_DEMAND node)**               |                                     | **~$150/month**                           |
| **Total (SPOT node)**                    |                                     | **~$125/month**                           |

The levers, in order of impact: the EKS control plane is a flat ~$73 and is
the single biggest line — worth a decision before enabling Milestone 11; the
NAT gateway (~$33) could be replaced by VPC endpoints (S3 gateway free,
ECR/STS/EC2 endpoints ~$7 each) at the cost of setup complexity; SPOT nodes
cut ~$20. RDS could shrink no further (`db.t4g.micro` is the smallest modern
class). Cross-AZ NAT traffic from the second AZ is included in the NAT
"processed" line and is pennies at demo scale.
